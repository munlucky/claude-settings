# 리팩토링 가이드라인

> 멀티-페이즈 리팩토링 작업을 위한 체계적 접근법.

## 핵심 원칙

1. **단계별 실행**: 대규모 리팩토링을 명명된 단계로 분할
2. **빌드 검증**: 각 단계 후 빌드 실행
3. **에러 분리**: 기존 에러와 신규 에러 구분

## 단계별 리팩토링 워크플로우

### 시작 전
1. 모든 단계를 명확한 설명과 함께 나열
2. 단계 분할에 대한 사용자 승인 획득
3. 기존 에러 캡처를 위한 baseline 빌드 실행

### 각 단계 진행 중
1. 다음 단계로 넘어가기 전 현재 단계 완전 완료
2. 영향받는 패키지의 빌드/타입체크 실행
3. 통과/실패 상태 보고
4. 다음 단계 진행 전 승인 대기

### 완료 후
1. 전체 통합 빌드 실행
2. baseline 에러와 비교
3. 변경으로 인해 도입된 NEW 에러만 문서화

## 빌드 검증 명령어

```bash
# TypeScript 프로젝트
npx tsc --noEmit --pretty

# 패키지별 빌드
npm run build -w <package-name>

# 전체 빌드
npm run build
```

## 에러 문서화 템플릿

```markdown
## 기존 에러 (baseline)
- [변경 전 존재했던 에러 목록]

## 신규 에러 (리팩토링으로 인한)
- [이번 리팩토링으로 인한 NEW 에러 목록]

## 빌드 상태
- Phase 1: ✅ Pass / ❌ Fail
- Phase 2: ✅ Pass / ❌ Fail
- ...
```

## 모범 사례

- **작은 단위**: 검증 가능한 작은 변경 선호
- **점진적 커밋**: 각 단계 성공 후 커밋
- **롤백 계획**: 빌드 실패 시 되돌리는 방법 파악

## 병렬 리팩토링 (멀티-패키지)

여러 독립 패키지에 걸친 리팩토링:

```
1. 독립 패키지 식별 (순환 의존성 없음)
2. 각 패키지별 별도 작업 컨텍스트 생성:
   - package1: Task 1 (격리된 스코프)
   - package2: Task 2 (격리된 스코프)
   - package3: Task 3 (격리된 스코프)
3. 병렬 실행 (멀티-세션 사용 시) 또는 순차 실행
4. 모두 완료 후: 통합 빌드 실행
5. 크로스-패키지 충돌 해결
```

**사용 프롬프트 예시**:
```
이 리팩토링을 패키지별로 분리해서 진행해줘:
- package-a: [구체적 변경사항]
- package-b: [구체적 변경사항]
- package-c: [구체적 변경사항]

각 패키지별로 빌드 검증 후, 마지막에 전체 통합 빌드 실행.
```

이 패턴은 변경을 격리하여 위험을 줄이고 빠른 반복을 가능하게 합니다.
