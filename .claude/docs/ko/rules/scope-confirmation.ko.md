# 스코프 확인 규칙

> 구현 작업 시작 전 항상 스코프 경계를 확인합니다.

## 구현 전 체크리스트

구현 작업 시작 전:

1. **IN SCOPE 확인**
   - 어떤 패키지/모듈/파일이 포함되나요?
   - 어떤 기능을 수정해야 하나요?

2. **OUT OF SCOPE 확인**
   - 어떤 패키지/모듈을 수정하면 안 되나요?
   - API 라우트는 명시적 요청이 없으면 제외인가요?
   - 데이터베이스 스키마/마이그레이션은 제외인가요?

3. **워크플로우 확인**
   - 사용할 특정 스킬이나 오케스트레이터가 있나요?
   - 해당 작업 유형의 커스텀 스킬이 있으면 즉시 사용

## 적용 시점

- 기능 구현
- 리팩토링 작업
- 다중 파일 변경
- 크로스 패키지 수정

## 스코프 확인 예시

구현 전 질문:
```
스코프 확인:
- IN SCOPE: [수정할 패키지/파일]
- OUT OF SCOPE: [수정하지 않을 패키지/파일]
- API 라우트 수정 필요 여부: 예/아니오
- 사용할 워크플로우: [스킬명 또는 기본값]
```
