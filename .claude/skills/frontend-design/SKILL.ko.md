# Frontend Design

사용자 대면 웹 UI를 구현하거나 리디자인할 때 사용합니다.

## 컨텍스트 프로토콜

디자인 컨텍스트 없이 시각 설계를 시작하지 않습니다.

다음 순서로 확인합니다.
1. 로드된 지침의 `## Design Context` 섹션
2. 프로젝트 루트의 `.impeccable.md`
3. 둘 다 없으면 `teach-impeccable`를 먼저 실행하거나 사용자에게 부족한 정보를 묻기

최소 필요 컨텍스트:
- 타깃 사용자
- 핵심 사용 사례 또는 해결하려는 작업
- 원하는 톤 또는 브랜드 성격

이 정보는 코드만 읽고 추론하지 않습니다. 코드는 구현 이력일 뿐 디자인 의도를 보장하지 않습니다.

## 적용 시점

다음 작업에서 사용합니다.
- React 또는 웹 프런트엔드 구현
- 랜딩 페이지, 대시보드, 설정 화면, 사용자 플로우, 시각 산출물
- 완성도, 개성, 제품 감각이 중요한 리디자인 요청

이 스킬은 저장소의 기존 디자인 시스템을 대체하지 않습니다. 이미 토큰, 프리미티브, 브랜드 규칙이 있다면 그것을 우선 따르고, 이 스킬은 실행 품질을 끌어올리는 용도로 사용합니다.

## 작업 원칙

코드를 수정하기 전에 먼저 시각 방향을 분명히 정합니다.
- 이 화면의 목적은 무엇인가
- 기본 템플릿이 아닌 어떤 톤을 택할 것인가
- 무엇이 기억에 남는 차별점인가

그 다음 다음 조건을 만족하는 실제 동작 코드를 만듭니다.
- 프로덕션급 기능 완성도
- 시각적으로 일관된 결과
- 데스크톱과 모바일 모두에서 의도된 동작
- 접근성과 유지보수성 확보

## 디자인 규칙

### 타이포그래피

- 기본 스택 대신 의도 있는 서체 조합을 우선합니다.
- 적절한 경우 `clamp()` 기반의 유동 타이포를 사용합니다.
- 두께, 크기, 간격, 리듬으로 계층을 분명히 만듭니다.
- 저장소 표준이 아닌 한 Inter, Roboto, Arial, 시스템 기본 글꼴에 자동 수렴하지 않습니다.

### 색상

- 명확한 위계를 가진 팔레트를 사용합니다.
- 가능하면 CSS 변수와 현대적인 색상 함수를 사용합니다.
- 무채색도 브랜드 색조로 약하게 틴트합니다.
- 보라-파랑 그라디언트, 어두운 배경 위 시안, 네온 포인트, 컬러 배경 위 회색 텍스트 같은 AI 스타일 기본값은 피합니다.

### 레이아웃

- 동일한 블록 반복보다 간격의 리듬으로 구조를 만듭니다.
- 위계에 도움이 될 때 비대칭을 의도적으로 사용합니다.
- 모든 것을 카드로 감싸기보다 강한 섹션 구조와 스페이싱 체계를 우선합니다.
- 중첩 카드, 템플릿형 히어로 지표, 반복 아이콘 카드 그리드는 피합니다.

### 모션

- 적은 수의 의미 있는 전환과 등장 효과에 집중합니다.
- transform과 opacity 기반 애니메이션을 우선합니다.
- `prefers-reduced-motion`을 존중합니다.
- 제품 의도가 분명하지 않다면 bounce/elastic easing은 피합니다.

### 인터랙션

- 핵심 액션이 몇 초 안에 보여야 합니다.
- 고급 정보는 점진적으로 드러냅니다.
- 빈 상태, 로딩, 오류, 성공 상태를 의도적으로 설계합니다.
- 키보드 포커스와 터치 타깃 가시성을 유지합니다.

### 반응형

- 모바일과 데스크톱을 단순 축소/확대로 보지 않습니다.
- 가능하면 유동 간격과 컨테이너 기준 레이아웃을 사용합니다.
- 모바일에서 핵심 기능을 대체 수단 없이 숨기지 않습니다.

### UX 라이팅

- 모든 문구가 역할을 하도록 만듭니다.
- 이미 보이는 정보를 반복하지 않습니다.
- 라벨은 직접적이고 구체적으로 씁니다.

## 안티패턴

다음은 경고 신호로 봅니다.
- AI 티가 나는 그라디언트와 글로우 위주의 다크모드
- 컬러 면 위의 회색 텍스트
- 장식용 글래스모피즘
- 중첩 카드와 반복적인 안전형 그리드
- 의미 없는 장식용 차트나 지표
- 기본 그림자가 들어간 둥근 박스 남발

## 연계 방식

- 시각 방향이 중요한 작업에서는 구현 전 또는 구현 중 이 스킬을 사용합니다.
- React/Next.js 성능 보정은 이후 `vercel-react-best-practices`로 처리합니다.
- 필요하면 `audit`, `normalize`, `polish`를 후속 스킬로 사용합니다.
