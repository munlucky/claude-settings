# Code Simplifier

## 역할

구현 직후, 최종 검증이나 리뷰 전에 코드 가독성 정리가 필요할 때 실행합니다.

이 스킬은 워크플로우에 통합되지만, 필요하면 명시적으로 직접 호출해 단순화 패스를 수행할 수도 있습니다.

## 핵심 계약

- 동작은 정확히 유지한다
- 최근 수정한 코드 위주로 작업한다
- 짧음보다 명확함을 우선한다
- non-trivial 변경은 검증 전에 더 단순하고 우아한 형태가 있는지 확인한다
- 불필요한 복잡도, 중첩, 중복을 줄인다
- 저장소의 코딩 규칙과 기존 패턴을 따른다
- 디버깅을 어렵게 만드는 영리한 재작성은 피한다

## 개선 대상

- 불필요하게 중복된 분기, 래퍼, 추상화
- 과도하게 조밀한 표현식과 중첩 삼항 연산자
- 의도가 흐릿한 이름
- 안전하게 합칠 수 있는 반복 로직
- 코드가 이미 말해주는 내용을 다시 설명하는 주석
- 최근 수정된 모듈 내부의 구조 불일치
- 기존 설계와 맞는 더 작은 변경으로 대체할 수 있는 hacky patch

## 금지 사항

- 명시적 요청이 없으면 최근 수정 파일 밖으로 범위를 넓히지 않는다
- 외부 동작, 데이터 계약, 부수효과를 바꾸지 않는다
- 코드를 빽빽한 one-liner로 압축하지 않는다
- 모듈 경계를 돕는 유용한 추상화를 제거하지 않는다
- trivial one-line 또는 명백히 올바른 수정에 elegance pass를 강제하지 않는다. orchestrator가 증적을 요구하면 skip reason을 기록한다.

## Balanced Elegance Check

non-trivial 동작/아키텍처 변경에서는:

1. future confusion을 줄이는 가장 작은 behavior-preserving cleanup을 찾는다.
2. 새 추상화보다 기존 local pattern을 우선한다.
3. 명확한 우아한 경로가 이미 보이면 hacky fix를 교체한다.
4. 추가 정리가 scope를 넓히거나 동작을 바꿀 수 있으면 멈춘다.

## 권장 워크플로우 위치

일반적인 순서:

1. `implementation-runner`
2. `code-simplifier`
3. `completion-verifier`
4. `codex-review-code`

## 출력

- 동작은 그대로인 정리된 코드
- 가독성이나 구조가 의미 있게 달라졌을 때만 짧은 변경 메모
