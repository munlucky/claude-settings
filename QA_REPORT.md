- Accepted trust-boundary limitations (deliberate, not unfinished work):
  - A judgment obligation is caller-attested by construction. `reviewerId` / `implementerId` are values the reporting caller supplies, so the T3 independence check (`reviewerId != implementerId`) is a structural requirement, not an identity proof. Making it authoritative would require either Host-issued session identity (moving the trust to the Host, not verifying it in the Kernel) or the Kernel invoking a reviewer model itself, which breaks the "Kernel plans, Host executes, no provider client" boundary (§5.1). Stricter-looking checks inside the Kernel would be theatre. What the Kernel does guarantee instead: a judgment can never satisfy an executable obligation, so every hard obligation at every tier still requires a Kernel-executed command.
  - Command binding is name-based. Semantic classes are derived from command names the *project* authors (manifest scripts, Makefile targets), which is why a reporting model cannot forge them — but a project that declares a `test` script doing nothing still satisfies `unit-test`. The Kernel does not and cannot judge whether a test is meaningful; it guarantees only that the command was project-declared, bound to the obligation, and actually executed by the Kernel.
  - `behaviorChanging` is pass-through, never inferred. A task that does not declare it stays at T0. Inferring it would make T1 the floor for essentially every task; the defence for undeclared behaviour change is instead the mutation rule — any run that changed the workspace requires Kernel-executed hard evidence to complete.
  - `blocked` / `required` network isolation is Linux-only (firejail/bwrap/unshare). On other platforms the request is refused rather than recorded, which is the honest outcome but leaves the policy unavailable there.
- Explicitly out of scope (operator decision, 2026-07-25): GitHub required-CI configuration (review item P2-17) is deferred. Consequence to carry forward — verification of this branch remains repository-internal self-attestation, and the three unexecuted paths listed above stay unexecuted. That is acceptable for `experimental` / controlled dogfood; it is the outstanding blocker for any `preview` or `stable-candidate` promotion, where a cross-platform matrix run would close both gaps at once.
