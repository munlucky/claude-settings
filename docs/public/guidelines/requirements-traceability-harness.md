# Requirements Traceability Harness

Canonical source guideline for tracing requirements through plan, implementation, and evidence.

Every requirement should map to an implementation owner and at least one verification signal.
Traceability records must show accepted, deferred, blocked, and changed requirements separately.
When scope changes, update the requirement mapping before changing closeout evidence.
Completion reports should reference scenario IDs or requirement IDs instead of only listing changed files.
