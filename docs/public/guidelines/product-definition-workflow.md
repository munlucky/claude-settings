# Product Definition Workflow

Canonical source guideline for product-definition planning artifacts and readiness review.

Product definition starts from user goal, target audience, main workflow, constraints, and explicit non-goals.
PRD, SPEC, DESIGN, and task slices should trace back to the same acceptance scenarios.
Use an assumption ledger for ambiguity; stop only when an assumption would create material product or safety risk.
Before implementation, review whether the plan is demoable, verifiable, and narrow enough to execute without hidden scope.

## Discovery Map Boundary

For large or foggy work, create a Discovery Map before PRD, SPEC, DESIGN, or phase planning claims execution readiness. The map may record destination, known facts, fog, candidate research, prototype, grilling, or task tickets, and out-of-scope decisions.

Resolved Discovery Map decisions can feed product artifacts only when they cite evidence and name the decision authority. Unresolved human decisions stay visible as decisions or blockers; they must not be downgraded to assumptions or converted into executable tasks by an agent.

Frontier language in product planning is advisory. It can identify unblocked planning candidates, but it cannot authorize worker fanout, plan graph parallelism, runtime-state completion, or live adoption.
