# Demo First MVP Gate

Canonical source guideline for demo-first product scoping and MVP readiness.

An MVP is demo-ready only when the primary user flow can be exercised end to end with representative data.
Scope cuts must preserve the core promise; defer supporting surfaces before weakening the main workflow.
Evidence should include the runnable URL, command, fixture, or artifact that demonstrates the flow.
Unimplemented features must be labeled deferred, not implied by navigation, copy, or placeholder controls.
