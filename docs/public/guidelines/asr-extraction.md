# ASR Extraction Guideline

Architecturally significant requirements are requirements that materially shape structure, integration boundaries, runtime behavior, data ownership, operational constraints, or verification strategy.

Extract ASRs from accepted requirements before architecture option generation.

Each ASR should have a stable ID, source requirement link, quality attribute classification, scenario, expected verification signal, and unresolved assumptions.

Do not treat every functional requirement as an ASR. Keep ASRs focused on decisions that influence architecture.

For Brownfield work, record whether each ASR preserves, extends, or conflicts with an existing architecture constraint.

Missing ASR extraction for non-trivial work blocks implementation handoff.
